# 串击击键当量 — 条件击键当量建模

> **命名说明（2026-09-29）**：项目目录已由 `击键测速` 改名为 **`串击击键当量`**（与姊妹项目 `并击击键当量` 对齐命名）。
> **数据文件 `数据/击键测速数据.tsv` 与 GitHub 仓库名 `conditional-keystroke-timing` 未改名**，脚本与路径引用一律照旧。

**条件击键当量**（Conditional Keystroke Equivalent，简称"当量"）：从个人打字测速数据中学习**前后键条件下**键位间的击键时间成本（ms，非物理距离），输出按键时间母表与 2/3/4 键总当量表（错误成本内含），用于输入法编码方案评估与键位优化。

**摘要**：传统键位成本模型用 2 键当量逐对累加，假设"打完一个键手就回位"。实测表明该假设系统性低估整串耗时，且低估幅度按键对类型不均（跨手 +32ms → 同手异指 +86ms，§5.4）——用其评估编码方案约 20.3% 的排序会被扭曲。本项目以"对称条件段"为单位建模：每段时间 `S(p,a,b,n)` 同时以前两键与**后继键**为条件，总当量 = 段当量之和；错误成本按段类计入，段当量 = 按键时间 + 错误成本（§4.6-§4.7）。固定 trial 测试集上总时间 MAE 33.9ms（R² +0.737）、排名精度 Spearman 0.835，4 码/3 码/2 键三档分别领先陈一凡 1986 群体两键表 39%/45%/49%（§5.3）；模型已贴实测噪声量级（§5.2）。

## 1. 引言

键盘输入的时间成本模型是输入法编码方案评估与键位优化的基础。传统工具（Carpalx、KLA 类）以 **2 键当量表** B(a,b)——键对 (a,b) 的击键时间——逐对累加估算整串耗时：

```
T'(abcd) = B(a,b) + B(b,c) + B(c,d)
```

其隐含假设：键对间独立，打完一个键后手回静止起始位。该假设在两个层面失实：

1. **串中键对的前键从不是"空"**：打完 `r` 后手指停在 `r` 位，击打 `w` 的起点不是 home 位——相邻间隔互为条件、上一键准备完成后可直接启动下一键（Rumelhart & Norman 1982 的"间隔负相关"与"不回位"）。
2. **低估幅度按键对类型不均**：有前键的中段比空前键首段慢（跨手 +32ms、同手异指 +86ms，§5.4）——统一比例修正处理不了"同手段被低估更多"的结构性错位，编码方案排序被扭曲（约 20% 排序不一致）。

本项目以**对称条件段**为单位直接建模：段 `S(p,a,b,n)` = "前两键为 p,a 时击打键对 (a,b) 的按键时间（含后继键 n 的准备成本）"，总当量 = 段当量之和：

```
T(abcd) = S(∅,a,b,c) + S(a,b,c,d) + S(b,c,d,∅)
```

2 键表是段模型在空前键（∅）+ 无后继（∅）下的特例切片——2/3/4 键当量同源同尺度，完全自洽。

主要结果与贡献：

- **对称条件段模型**：前键条件效应 +31~+85ms 且按键对类型不均（§5.4）、后键条件化（φsuc7，v2 落地设计）——单一段表示统一 2/3/4 键当量
- **个人稳定期数据全链路**：2/4 键混采协议（欠样本加权、随机延迟去节律）、稳定期边界方法（自动剔练习漂移，§5.1）、B4b 两阶段残差异常剔除（§4.5）
- **部署混合模型 v5**（XGB + 神经分量 ×5 固定种子平均，无选优噪声；段角色 φ35，2026-10-10 删冗余列）：固定 trial 测试集 T₄ 总时间 MAE 34.0ms / R² +0.739 / 4 码排名 Spearman 0.835，T₃ 留出 25.3ms（§5.2），4 码/3 码/2 码三档分别领先陈一凡 1986 群体两键表 38%/45%/48%（§5.3）
- **段类条件错误率模型与段当量**：错误成本（错误率 × 实测错误修正时间，随采集动态更新）按段类计入，"当量"完整定义 = 按键时间 + 错误成本（§4.6-§4.7）
- **样本量终局**：模型已贴实测噪声量级（段组内 σ≈33.3ms，§5.2），专项扩容零收益

**界面反馈（2026-10-08 用户要求：试次结束后只显示时间）**：屏上文字提示只给段时分解——**2 键 `xxms`、3 键 `xx+xx=xxms`、4 键 `xx+xx+xx=xxms`**（段时 = 按键间 delta ⇒ 等号右边是总时；取各段"显示值"之和以保证等式自洽，落盘仍写原精度）。打错时仍显示 `✗ 输入: …`（打字过程中已有 `✗ 期望 X` 即时提示），空格跳过显示 `␣ 已跳过`。

**2/4 键混采**：每试次以 P2=0.30 概率出 **2 键码**（其余 4 键）。2 键试次服务对称段模型的 T₂ 角点 S(∅,a,b,∅) 测量——4 键试次的首段总带真后键，该"词首+词末"组合只能靠 2 键试次直接测量。2 键与 4 键各用**独立的欠样本键对池**：4 键池喂段覆盖，2 键池喂 900 键对的角点覆盖；2 键行 code 长度 2、c_d/d_d=0 填充，下游按 `len(code)==4` 过滤。

| 操作 | 行为 |
|------|------|
| 输入显示的 2/4 个字符 | 正常打字 |
| 输错（任意键） | 立即变红停止，进入随机延迟 |
| 空格 | 跳过当前组（不记录），进入随机延迟 |
| Esc | 退出 |

**采样策略（多样性加权）**：首键均匀随机，后续键按 `w(b|a) ∝ 1/(n(a,b)+1)` 加权——欠样本键对优先（符号键 `;,./` 零样本时自动补足），键对样本量趋均衡后自动回归均匀随机。每次试次结束（正确/错误/跳过统一）延迟 **300-800ms 随机**再显示下一组，打断固定节律，防止"预期性击键"把键对难度差异压缩平均。

**输入法（2026-10-01，两个采集脚本同此）**：**无视输入法状态** —— 采集时不必切英文。修法两层，实现在共用模块 `采集输入层.py`：

| 层 | 调用 | 说明 |
|---|---|---|
| ③ 进程级 | `ImmDisableIME(0)` | **必须在建第一个顶层窗口之前**调用（MSDN 硬约束）⇒ 放在 `__main__`/`__init__` 建 `tk.Tk()` 之前。成功 ⇒ 本进程不加载输入法 |
| ② 窗口级 | `ImmAssociateContext(hwnd, NULL)` | 建窗后摘掉本窗口输入上下文；窗口激活时与每 2 s **重摘**（系统会重新关联） |

为什么必须处理：输入法中文态下，字母先被 IME 拿去组字 ⇒ tkinter 的 `<KeyPress>` 只带 `keysym='??'` / `char=''`，采集脚本读 `event.char` 会判定"没有按键"（**整场数据都收不到**）；IME 还会输出汉字、弹候选框。实测复现与两层效果见 `实验/实验-IME禁用验证.py`（真实注入按键：布局 `ImmIsIME=True` 的中文态下, 四键仍以干净 `char` 到达并正确落盘）。排障：`--no-ime` 关掉这两层（回到旧行为）。
（同源项目 `../并击击键当量/` 在此之上还有第三层**低层键盘钩子**——在 IME 之前就把键吞掉, 保证"输入法连键都看不到"; 串击实测 ②+③ 已足够, 故不引入全局钩子。**无全局钩子 ⇒ 事件源仍是 tkinter `<KeyPress>`、时间戳语义不变 ⇒ 已采数据与本文下面的全部口径不受影响**——改动只影响"中文态下收不到键"这一失效场景，英文态行为与改动前一致。）

## 4. 方法

### 4.1 问题定义

给定 4 字符编码 `abcd`，预测击键总时间 T（ms）。训练数据每行记录一个随机 4 字符串的实际击键时间戳。

### 4.2 对称条件段模型（v4 混合部署 · 段角色感知）

将序列拆成**段**（n 键码 → n−1 段），每段独立预测，条件 = **段角色 + 前两键 + 后继键**：

```
每段 t = MLP(e, φ35)   S(角色,p,a,b,n) ≈ MLP([e_p;e_a;e_b;φ35])   (95→128→64→1 + Dropout0.2)
  双线性交互 3 项 e_pᵀW₁e_a + e_aᵀW₂e_b + e_pᵀW₃e_b **已于 2026-10-10 删除**（见 §4.4 ⑪）
  前键空/无后继 = 索引 30（∅）
  φ35 = φ8(a,b) 几何 + φsuc7 后键 [存在, 同手(b,n), 同指(b,n), 同键(b,n), Fitts(b,n), 同手(a,n), Fitts(a,n)]
        + 角色块 3 维 [i==3, L==3, L==4]   (i=段位, L=码长; 09-21 落地, 10-10 删冗余列 4→3)
        + pa/pb 几何块 17 维 [存在(prev), φ8(prev,a), φ8(prev,b)]
          (2026-10-07 落地, v5; prev=∅ 时整块为 0。**只有一个存在位** —— pa/pb 的存在性恒等。依据 §5.8)
  三类视图 = 角色 5 [段位==3, 码长==3, 码长==4, 存在(p), 存在(n)] / 键特征 0
           / 跨键特征 30 [ab8 pa8 pb8 bn4 an2]（原「学习型双线性 3」已于 10-10 删除）
                                                (跨键按 ab pa pb bn an; 完整清单与维数核对见 §4.4)

段角色 (码长 L, 段位 i) — 等价的 6 类:
  L2i1 角点 S(∅,x,y,∅) · L3i1 / L4i1 首段 S(∅,x,y,z) · L3i2 短尾 S(x,y,z,∅)
  L4i2 中段 S(w,x,y,z)   · L4i3 长尾 S(x,y,z,∅)
  为什么必需: (p,a,b,n) 只编码「是否首段/是否末段」——3 键 seg2 与 4 键 seg3 签名相同
  ((有前键,无后键)) 却是不同角色, 单表无法表达 (与错误侧 09-19 段类重参数化同因)

部署混合 (BlendModel): S̄ = 0.3×XGBRegressor(独热122+φ35) + 0.7×mean_{s∈{0..4}} S_deep2(s)
  无选优环节 → 无选优抽签噪声 (决策带从 ±3 缩至仅测试重洗 ~±1ms), 同数据逐位确定

整串当量统一公式 (n 键序列 k₁k₂...kₙ; 首段前键=∅, 末段后键=∅):
  两键  T₂(xy)   = R(L2i1)[x,y]                                       ← 1 段 (角点, 2 键试次实测内插)
  三键  T₃(xyz)  = R(L3i1)[x,y,z] + R(L3i2)[x,y,z]                    ← 2 段
  四键  T₄(wxyz) = R(L4i1)[w,x,y] + R(L4i2)[w,x,y,z] + R(L4i3)[x,y,z] ← 3 段
```

### 4.3 模型结构

输入四元组 `(p, a, b, n)` 中三键 `(p,a,b)` 经**共享嵌入**与**交互部分**两条路径汇合后加 MLP 头，后键 `n` 经 φsuc7 特征进入 MLP（sym_phi 形式）。部署为混合（XGB 分量 + 神经分量×5 平均）。

```
输入: ids = [p, a, b, n]（31 索引, n 仅经 φ 生效）, φ35 = φ8(a,b) + φsuc7(b/a, n) + 角色块 3 维 + pa/pb 几何块 17 维
共享: e_p, e_a, e_b = E_key[ids[:, :3]]   E_key ∈ ℝ³¹ˣ²⁰（30 键 + ∅）
```

**① 神经分量（deep2 v6，21,357 参数）**——键位嵌入 + φ 特征 + 深化 MLP：

```
S(角色,p,a,b,n) = MLP([e_p; e_a; e_b; φ35])        ← 双线性 3 项已于 2026-10-10 删除
```

| 组件 | 形状 | 说明 |
|------|------|------|
| E_key | 31×20 | 通用键位嵌入（p/a/b 三槽共享；n 不嵌入，只经 φsuc） |
| MLP | 95→128→64→1 (ReLU+RMSNorm+Dropout0.2) | 非线性主体（含 φsuc 后键 + 角色块 + pa/pb 几何块）；dropout 使集成成员去相关、放大预测平均收益 |
| ~~W₁/W₂/W₃~~ | ~~3 × (20×20)~~ | **已删（2026-10-10）**：原为显式二阶交互（前键×首键、首键×次键、前键×次键），实测在现行 φ 体系下被 φ8(ab/pa/pb) 键对几何替代 ⇒ 删它省 1,200 参数且不亏（§4.4 ⑪） |

**② XGB 分量（确定性）**——XGBRegressor（500 树 / lr 0.06 / depth 6 / subsample 0.8 / colsample 0.8），设计矩阵 = 独热 **31+30+30+31 = 122** 维 + φ35 = **157 维**（**只有 prev/nxt 能取 ∅，a/b 恒为真实键故各 30 列**——2026-10-08 去掉两列恒零的 a槽∅/b槽∅，见 §4.4 编码说明）；种子稳定 ±0.18ms；自适应部分模式匹配（叶子 = 部分键模式 + φ 区间），对零样本组合外推同样有效（见过/未见三元组分组验证优势均匀）。

**③ 混合**：S̄ = 0.3×S_xgb + 0.7×mean(S_deep2, seeds 0-4)。

**模型选型依据（09-14 当前数据全家族重跑，`实验/实验-架构对比{,2,3}.py`，原始 test 口径、神经 5 配对种子）**：全局最优 = 本混合 41.6ms / R²+0.592（对 ens5 −0.6、对单模最优 XGB −1.1、对神经单模 −2.4）。各类最优——**树系** XGB 42.7（单模最优，HistGBM 43.9 / RF 45.5 / ET 51.7）；**神经系** base 44.0（容量维 de32/dh128/再加深均持平 Δ≤0.2；结构删件全显著：no_w3 +2.6 / mlp_only +2.1 / bi_only +3.6 / 删φ +1.7）；**组合系** ens5 42.2。维持废弃：FT-Transformer 48.7（慢 ~12×）/ ResMLP 47.1 / 全局 FM 47.0 / 高斯秩目标 51.6 / 注意力聚合 47.4 / CP 张量分解 48.7 / 核方法 48.1 / kNN 70+ / ridge 49.0；目标函数 l1 / huber50 与 mse 已无差（±0.2）。

### 4.4 键位嵌入与几何特征

键盘为 **3 行 10 列完整 QWERTY（30 键）**：26 字母 + `; , . /`。每键独立可学习向量 `e_k = E[k]`。当量定义：**期望键对耗时，单位 ms**（模型预测原始值，不做相对归一化）。

键位嵌入本身不含手指归属信息，故显式注入几何特征。**这些特征按「依赖哪些键」分三类（2026-10-10 重组，与错误侧 §4.6 同一套口径与命名：角色 / 键特征 / 跨键特征；跨键按 ab pa pb bn an）**：

**φ35 = 角色 5 + 键特征 0 + 跨键特征 30**（2026-10-10 删掉角色类里那 1 维严格冗余后，φ36 → φ35）

| 类别 | 归属 | 维 | 特征（列序即该族内部顺序） |
|------|------|----|------|
| **角色** | (码长 L, 段位 i) + p/n 是否存在 | **5** | 段位==3 · 码长==3 · 码长==4 · 存在(p) · 存在(n) |
| **键特征** | 键·p / 键·a / 键·b / 键·n | **0** | —（四槽的「键特征」就是身份本身，由共享嵌入 + 独热承载；**不存在"单键几何"**，故这一类在时间模型里为空） |
| **跨键特征** | 跨键·ab | 8 | 同手 · 同指 · 同键 · 列距 · 行距 · Fitts · 镜像手指 · 跨行同指 |
| | 跨键·pa | 8 | 同上 8 项 |
| | 跨键·pb | 8 | 同上 8 项 |
| | 跨键·bn | 4 | 同手(b,n) · 同指(b,n) · 同键(b,n) · Fitts(b,n) |
| | 跨键·an | 2 | 同手(a,n) · Fitts(a,n) |
| | ~~跨键（学习型）·ab / pa / pb~~ | ~~3 项~~ | **已删（2026-10-10）**：原为双线性 `e_pᵀW₁e_a + e_aᵀW₂e_b + e_pᵀW₃e_b`（秩 ≤20 的键对因子分解），实测被 φ8(ab/pa/pb) 的显式键对几何替代 ⇒ 见 §4.4 ⑪ |
| | 跨键（学习型）·bn / an / pn | 0 | 未加（bn/an 无证据；**pn 一律不加**：T₄ +0.01 / T₃ +1.26 纯负担——**其"存在性"已归入 角色**） |

**存在(p) / 存在(n) 为什么归「角色」而不是「键特征」**（2026-10-10 用户定）：两个位都是**位置信息**而非键属性——p=∅ ⟺ 首段、n=∅ ⟺ 末段，它们描述的是"这一段在码内的位置"，与 (码长, 段位) 同一性质。错误侧一直把「有后键」放在角色电平里（β），这样归后两侧口径完全对齐。

**每族用同一个 8 项定义函数**（代入各自的键对；键特征类为空是结构性的——各槽身份由共享嵌入+独热承载，只有能取 ∅ 的 p/n 需要存在位，而存在位已归角色）：

```
φ8(x,y) = [same_hand, same_finger, same_key, col_dist, row_dist, fitts,
           mirror_pair, cross_row_same_finger]

same_hand(x,y)  = 1  如果 x 和 y 在同一只手（左手=col 0-4，右手=col 5-9），否则 0
same_finger(x,y)= 1  如果 x 和 y 用同一根手指按下，否则 0
same_key(x,y)   = 1  x==y 同键重复（零幅移动需单独建模, 不适用 Fitts）
col_dist / row_dist  = |列差| / |行差|（İşeri & Ekşioğlu 2015: 列>行>手 重要性）
fitts(x,y)      = log2(1 + √(col² + (2·row)²))   Fitts 对数项, W=键宽, 行距≈2 键宽
mirror_pair(x,y)= 1  异手对称手指（Grudin 1983: 换位错误集中于镜像手指）
cross_row_same_finger(x,y) = 1  同指跨行（keygen: 同指顶↔底行最慢最易错）
```

**重组后看清的三个结构事实**：

1. **角色类的 6 维里有且只有 1 维严格冗余，已在 2026-10-10 删除（φ36 → φ35）**——**语义先定死：存在(p)=1 ⟺ 有前键 ⟺ 段位≥2**（p=∅ ⟺ 首段；故它不是"首段标志"）。于是 **存在(p) ≡ (段位==2) + (段位==3)**，**就是角色块两列之和**（精确恒等、连截距都不需要）⇒ 加上它**秩不变、信息不变**，是原 φ36 里唯一严格冗余的一列。反过来 **存在(n) 不可去**：存在(n) = 码长==3·(1−段位==2) + 码长==4·(1−段位==3)（即"非末段"，**含 2 键角点修正项**——角点段位虽为 1，其 n 同样是 ∅）——**乘积型，不在角色块张成内**（最小二乘投影残差非零，已在真实设计矩阵上验）⇒ 它恰好补上"加性块"缺的那一维（段位×码长交互方向）。秩的账：`{1, 段位==2, 段位==3, 码长==3, 码长==4}` 秩 5（对 6 个角色均值留 1 个约束），**并入 存在(n) 后秩 6 = 满秩 ⇒ 角色均值可自由拟合（饱和）**。既然两个存在位都保留，则段位那一对只能留一个（**`段位==2 ≡ 存在(p) − 段位==3`**，对称式亦然）⇒ **落地形式 = 角色类 5 维 {段位==3, 码长==3, 码长==4, 存在(p), 存在(n)}**：对 6 个角色两两可分辨且秩 6 = **最小饱和参数化**（原 6 维是"饱和但含 1 冗余列"：7 列装 6 维；现 5 维是 6 列装 6 维）。⚠ **本块单独不再两两可分辨**（L3i1/L3i2 与 L4i1/L4i2 各撞码），可分辨性来自与两个存在位的组合。⚠ 方法学教训：这类"严格共线"的断言**不能靠语义直觉下**——本轮把 存在(p) 的方向读反了两次（先写 `1−(段位==2)−(段位==3)`、再写 `(码长==3)+(码长==4)−(段位==2)−(段位==3)`），两次都被**真实设计矩阵的逐元素 max\|Δ\| 比对**（=1.0）当场抓出；凡恒等式断言必须落到"在真实矩阵上逐元素验证"这一步。推导、秩表、五臂实测与落地漂移见 §4.4 ⑥ 与 ⑦。
2. **存在位归角色（而非键特征）**：两个位都是位置信息（p=∅ ⟺ 首段、n=∅ ⟺ 末段），与 (码长, 段位) 同一性质；错误侧一直把「有后键」放在角色电平里（β），这样归后两侧口径完全对齐。
3. **各族完备度不对称**：ab / pa / pb 取全 8 项，而 bn 只 4 项、an 只 2 项（φsuc 起源）。历史上测过把 bn/an 扩到全 8 ⇒ **an 去掉全 8 反而更好（T₄ −0.19）、bn 打平（+0.02）**；现状子集内 6 维逐维 LOO 全为正（bn 最承重的是 Fitts）⇒ **一维都删不掉，维持现状**（详表 §5.8）。

⚠ **本表是按「依赖哪些键」的分类，不是 φ35 的实际列序**，两者正交：设计矩阵里的实际拼接仍是历史叠加序 `[φ8(a,b) | φsuc7(存在(n)+bn4+an2) | 角色块3 | 存在(p)+φ8(p,a)+φ8(p,b)]`（改列序会使旧权重不兼容）。XGB 侧消融用的块名与三类的对应关系：`ab8` = 跨键·ab 全部 8 项；`suc7` = 存在(n) 1 + 跨键·bn 4 + 跨键·an 2；`role3` = 角色块 3（2026-10-10 前为 `role4`）；`papb17` = 存在(p) 1 + 跨键·pa 8 + 跨键·pb 8（见 §4.9 的 XGB 侧几何消融）。

**消融结论**：逐特征 leave-one-out 全部持平（特征互为冗余），但整体删除损失 +1.7ms、角点 +3.2ms（09-14 当前数据复测，与 08-14 原测同值）——φ 作为整体提供嵌入补不上的几何先验，价值在稀疏三元组外推（2/3 按键时间表条目零样本）。手工指对类别编码（独热）与键嵌入+双线性等价（嵌入本身即更细的键对类别表示）；生理学导向改造（指距替代列距等）经两轮独立批实验全部关闭，φ8 维持。

**键位编码（XGB 分量）**：4 个槽位 (p,a,b,n) 用**各自基数的独热**——`prev` 31 列、`a` 30 列、`b` 30 列、`nxt` 31 列（30 键 + ∅），合计 **122 列** + φ35 = **157 维**。**为什么各槽基数不同**：只有 `prev`/`nxt` 能取 ∅（首段无前键、末段无后继键，实测各 7336/17292 段为 ∅），**`a`、`b` 是实际按下的两键、恒为真实键**（调用点保证）⇒ 各只需 30 列。

### 4.5 训练协议

- **目标**：批量 MSE（段级），验证集 20%，早停 patience=60，Adam lr=0.001
- **训练形态（无选优）**：固定种子 0-4 训练 5 个神经分量取**预测平均**，与确定性 XGB 混合部署——同数据逐位可复现。选优环节（best-of-N）曾引入 ±2ms 抽签噪声（验证最优候选可为测试最差），已移除
- **可复现性与并行**：模块导入即固定运行环境（单线程+播种）；训练成员构造显式种子化 → 每成员 = (seed, 数据) 纯函数，全流程 25 次训练经 spawn Pool 并行（多核 `--full` 约 4 分钟），`KJ_SEQ=1` 强制串行；并行/串行产物逐位一致
- **验证集泄漏**：同一 trial 的三段共享个人速度因子（trial ICC 0.308），段级随机划分使验证集系统性乐观 ~9ms——**模型对比与报告口径必须用 trial 级留出**（§5.1）
- **异常剔除（B4b 两阶段残差，键对分桶）**：
  - **数据准入**：唯一数据源 `数据/击键测速数据.tsv`，**error=0 才入**，段时严格递增校验（4 键 b_d<c_d<d_d / 3 键 b_d<c_d）；**段时 = 按键间 delta**：首段 b_d，中段 c_d−b_d，尾段 d_d−c_d
  1. 段位分桶 MAD k=3 剔除 → 训练 M0（干净模型提供"期望行为"）
  2. M0 推全数据 → 带符号残差 `y−ŷ`（正 = 比预期慢）
  3. 残差按**键对 (a,b) 分桶**、**单侧上围栏**（r ≥ med + 3·1.4826·MAD）剔除——只删"比该键对合理预期慢"的段（注意力中断只拖慢不加快；偏快是 rollover/预备连击的真实行为不删）。剔除率随池变化（当前稳定期池实测 ~2.7%，早期快照 ~4.8%；van Selst & Jolicoeur 1994 调研范围 5-10% 内）
  - 依据：全局残差法会把"模型学不会的难键对"的真实慢段当异常删（用模型偏见定义正常，循环论证）；键对分桶修复当量失真。剔除收益在**当量稳健性**而非预测精度（无剔除与 B4b 的测试 MAE 在噪声内）。**测试集需用独立剔除（固定流可复现）**
  - **剔除单位 = 整 trial（2026-10-08 用户决策）**：一个 trial 内任何一段超 MAD/键对围栏 ⇒ **整条 trial 不入训、不入评**（含错 trial 那条在数据准入就已整体排除）。依据：**段模型带 4 键上下文**，同 trial 的段共享该 trial 的速度状态与上下文，某段被判异常时其余段很可能同样被污染——逐段剔除会把"半污染 trial"的残段喂给模型。落地：新增 `trialwise_keep()`（逐段掩码 → 整 trial 掩码），**第 1 阶段 M0 的训练集与第 2 阶段判定都升级**；`KJ_TRIALWISE=0` 回退逐段口径（仅供复现历史数字/受控对比）。**影响实测**：逐段口径下训练池有 470/7854 trial 属"被剔段但其余段仍入训"（占保留段 4.8%），整 trial 口径下训练池 18261→**17292 段 / 7336 trial**、部署池 22854→**21715 段**。**副产品：两层指标的关系变成精确恒等**——段级 n = 段数 × 总级 n（T₄ 3390 = 3×1130、T₃ 408 = 2×204），总级偏差 ≡ 段数 × 段级偏差。
  - 原「整 trial 级排除」只有稳定期边界（§5.1：按 150-trial 块切、整 trial 剔除练习漂移期）；⚠ 训练内部的 80/20 验证集划分仍是**段级**随机（已知泄漏 ~9ms，故报告口径一律用 trial 级留出）。
- 段样本：每 trial 3 段（t₁: 空→ab, t₂: a→bc, t₃: b→cd），共享 MLP 头，段间互相增强

### 4.6 键对错误率模型与错误修正时间实测

**① 错误率 P_err（`分析-错误率.py`，全量数据）**：

```
P_err(a,b | 段类) = σ(w·feat(a,b) + β·有后键 + δ·(段位−1))          ← 纯加法（2026-09-21 去交互项）
段类 = (有前键, 有后键, 段位)，共 5 类（由 码长×段位 映射；2026-09-19 重参数化）

当前拟合（44089 键对事件 / 825 错误，1.87%）:  β=+0.452 ± 0.119 (z=+3.81)   δ=+0.887 ± 0.079 (z=+11.22)

  实测率（事件口径）: c0 0.41% / c1 0.90% / c2 1.55% / c3 2.06% / c4 3.18%

```

**交互项 γ 已删（2026-09-21 用户决策）**：γ(有后键×段位) 在段类重参数化后的口径下历次都不显著（−0.10±0.17, z=−0.58），而**判定它需 ≈638,000 trial 数据**（§5.7）、点估计 ≈0 意味其对总当量影响在第四位——删掉换 2 个自由度。收益立刻兑现：**β 的 SE 从 0.270 降到 0.125（z 由 2.1 升到 3.6）**，因为 γ 与 β 共线，去掉约束后那份信息回到 β（LRT 监控 D=0.344, df=1, p=0.56 → 加法形式不被数据拒绝）。**`分析-错误率.py` 每次运行都会并排拟合一次带 γ 的版本并报 D/p**，作为"删得对不对"的常设监控。段当量随之变化 ≤0.6ms/段（T₂ +0.5 / T₃ +0.3 / T₄ −0.2ms）。

**为什么不再用四类签名**：旧签名 (有无前键, 有无后键) 在**仅 2/4 键数据**上与 (码长, 段位) 一一对应——是无损重参数化，当时既不会错也看不出来；加入 3 键后「尾段」类被劈为 c2（3 键段 2，实测 1.64%）与 c4（4 键段 3，实测 3.15%，z=−3.08, p=0.0020），旧模型显著拟合不足，新五类模型 D=0.14（p=0.71，09-19 复核）/ 09-21 复核旧四类 D=8.87（p=0.012）、五类 D=1.31（p=0.52）。同时**「有前键」不再单列**：观测数据里 有前键 ⟺ 段位≥2 完全共线，旧模型的 α=+2.10 实为位置效应，引入段位项后塌缩为 0（z=0.02）。段类的物理含义：**起始保护**（c0 角点 0.57% ≪ c1 首段 0.89%）、**末位保护**（同段位下无后键更低，β>0）、**码内累积负担**（无后键三格随段位 0.41→1.64→3.15%，δ）。

**② 错误修正时间 cost（`采集-错误修正时间.py` + `分析-错误修正时间.py`）**：连续长随机串（120-200 字母）+ 自然回退纠错，单框逐字符着色（白=未打/绿=对/红=错）——错误发现以立即型为主，对应短码语境。测量"**首错按下 → 首错位置打对**"的净耗时（反事实世界尾段同节奏平移，原始区间即净成本）；连锁错（含同位二次错）吸收为单事件——错误只计首错、时长只记首错间隔；episode 判定在采集端实时完成，只落盘错误键事件与串汇总（`数据/错误修正时间-错误键.tsv`）。

**时长异常剔除（分析端）**：过程分桶（发现型 imm × 退格数档）桶内单侧 med+3×1.4826×MAD 围栏——语义同 S 模型剔除（注意力中断只拖慢不加快，只删过大侧）；退格/盲打是时长的过程簿记结构（+~400ms/退格、+~350ms/盲打字母）**必须分桶**，否则误删合法的连锁/盲打长纠正；桶 n<8 不设栏（保守）；剔除只作用于时长统计，事件计数与率仍用全部闭合 episode。

**当前实测**（282 事件 / 22959 按键 / 12 有效坐姿，弃首坐姿+围栏剔 4 后 n=278）：全体 782ms（SE 15）/ 立即发现 701ms（n=212）/ 延迟发现 1042ms（n=66）。双成分结构：延迟 = 立即 + 过程增量（回归截距与立即均值差 +4ms 定量成立）。

**定案机制**：续采监控，三判据全满足即冻结 cost——①簇稳健 SE≤30ms（均值位置钉住，T₄ 传导 <±2ms）②近 10 坐姿斜率不显著（近端窗口）③近 5 坐姿均值与全体差 <40ms；监控规则：单次刷新均值变动 >±75ms（2×簇SE）回查。**现值（2026-09-22）① 29ms ✓ / ② t=−2.52 ✗ / ③ 差 −72ms ✗，约束项 = ③**（② 会随窗口自然转好，③ 是平台检验——需坐姿均值走平，只差 +278 episode；测算见 §5.7 与 `实验/实验-错误修正成本定案测算.py`）。cost 为乘法标量，对优化排名零影响、只定绝对刻度。导出 `产物/错误修正时间-实测值.txt`（label 行式：cost_ms 数据行 + 手别诊断行——左/右手目标纠错差 +69ms（t=4.1，同手纠错串惩罚，退格位依赖的布局结构），为当量表通用性不入表）。

### 4.8 设计边界

- ❌ **字母 N-gram 频率**：不引入自然语言熟悉度偏差，纯随机采样
- ❌ **连组模式**：每组独立开始（模拟分词间自然停顿），不建模组间转移
- ❌ **节奏/节拍器**：随机延迟打断节律，按"打对条件下尽可能快"测试
- ❌ **变长编码**：仅测 2/4 字符编码（3 键当量为按键时间表切片组合）
- 🎯 **应用域 = 4 码内**：当量的优化与使用仅限 4 码内词内评估（主要 4 码二字词，词间自然分词间隔）——孤立 4 键试次的范式与真实词内输入结构一致；跨词连续序列不在建模范围

## 5. 结果

### 5.1 评估口径

**三档同报表（2026-10-08 用户要求「2、3、4 键需汇报同样多的统计数据」）**：T₂/T₃/T₄ 一律由 `分析-按键时间.py` 的 `bias_triplet` 单函数产出，字段与定义完全一致（n_trial / 段MAE / 总MAE / R² / 总级偏差±SE / 段级偏差±SE / 段位偏差分解），**偏差 = 预测 − 实测（负 = 低估）**——完整定义见 §5.2 开头。`实验/实验-数据充分性估算.py` 的「一、时序侧」表直接复用该函数（不再自行实现），故两处数字必然一致。此前 T₂ 的偏差是反符号且三档各缺字段（T₄ 无偏差、T₂ 无总MAE/R²、T₃ 无段MAE），本轮只统一**报表**，未动任何**估计量**：重构后 `--full` 产物与重构前**逐位一致**（md5 对照）。

**统一口径：稳定期内固定 trial 测试集**。`stable_pools`（分析-按键时间.py）边界方法（序号块口径；**2026-09-19 起分码长各自计算**）：各码长的正确 trial（4键 d_d / 2键 b_d / 3键 c_d 各自）按时间序切等大块（**一律 150 trial/块** —— `_block_boundary(tots, block=150, band=1.10, ref_last=5, smooth=3)`）→ 每块总时中位 → 3-块滚动中位平滑 → R = 末 5 块平滑值中位 → 自末向前最早连续满足 平滑值 ≤ R×1.10 的块起（确定性无随机）。三种码长入队时间不同、练习轨迹各自独立故各自截取（旧「4 键边界 + 2 键同截归属」在 2 键无趋势时曾等价，**2026-10-08 起 2 键边界离开块 0 后不再等价**）；稳定块数 < 8 的码长照常截取并告警（3 键 09-19 补采期曾是此状态，现已达 11/18 块）。稳定期内 seed 2024、20% trial 留出（各码长分别 permutation，顺序 4→2→3 固定），训练/评估只作用于训练侧，测试集独立 B4b（内部自训 M0，与训练无信息交换）。`python 分析-按键时间.py` 直接输出（确定性流，重跑必得同值）。**部署模型同用稳定期全量**（当量表 = 当前状态语义）。**例外：错误率模型（分析-错误率.py）仍用全部数据**（用户决策不随练习过滤——切稳定期会把错误事件砍到 ~40%、系数方差放大约 1.5 倍，而错误率的练习效应仅 +0.4pp/6 周，折算 <2ms/段在噪声下）。⚠ **`练习效应.png` 的 B/C 面板曲线用 75/40 trial/块是「显示粒度」**（只为看清形状），其边界标注一律取上述官方 150/块结果 —— 细粒度下块间方差大、R×1.10 带更难连续满足，边界会被推后（2 键细粒度读作块[32]，官方为块[12]），**勿用该曲线读边界**（2026-10-09 修图时发现并已在图上写明）。

当前快照：稳定期 = 序号块[38]（全局 ok 行 #5701）起、4 键 5964 + 3 键 1490 + 2 键 2220 trial（R=346ms）；测试集 4 键 1192 + 3 键 298 + 角点留出 444。**训练池 = train4 + train3 + train2**（3 键入训是段位块 L==3 维可辨识的前提，2026-09-21 起）。

**跨快照噪声带**：无选优环节 → 无选优抽签噪声；剩余波动仅测试集重洗（数据增长 → N 变 → seed 2024 permutation 重抽，~±1ms）。跨快照的"旧模型×新测试"对比不可用（训练池与对方测试集 ~80% 重叠 = 泄漏）。

**为什么用保留口径（B4b 剔除后）**：

1. **用途匹配**：当量表服务于编码方案评估与键位优化（相对排序）。被剔段是注意力中断，与键对难度无关、对候选编码近似同分布的加性噪声——计入指标只稀释难度信号，不提供方案设计信息
2. **训练分布一致**：按键时间表在 B4b 保留段上训练，保留口径测试集与之同分布
3. **错误成本已独立建模**：错误率 × 错误修正时间由 §4.6 显式承担；中断率属会话/状态变量，不是键位属性

全口径定位：**真实场景下界**——若要预测含走神的绝对打字时间，需另建中断率模型；两口径之差即中断段（测试 ~5%）的不可预测性代价。

① **主指标仍是绝对 MAE**（同一快照内比较）—— 决策带 ±3ms、重洗带 ±1ms、偏差 SE 全部标定在绝对量纲上，换主指标属口径变更，历史阈值与快照会一并失效；
② **并列报 `nMAE`（%）作为跨期/跨人可比层**（**已落地：三档报表与陈表三档对比均并列输出 mean 与 nMAE**）—— 零成本，且让三档首次可比：**T₄ 总 9.57%（段 18.10%）/ T₃ 12.02%（段 19.72%）/ T₂ 21.97%**，即绝对量最小的 T₂（17.0ms）在相对量上反而是**最难的一档**（角点只 77.5ms 长，同样 17ms 误差占 22%）；分角色看 5 个角色的 nMAE 落在 15.8~20.9%（跨度远小于绝对 MAE 的 17.2~24.8ms）⇒ 相对量确实是更对齐的视图；
③ **跨快照务必连 `mean(y)` 一起报**（否则相对量无法回填 —— 历史快照大多没记分母）；跨人时把分母换成**该人自己的 mean(y)**，并并列报 **scale 不变的 `min_k MAE(k·p, y)`**（即对陈表已在用的 ×k 机制，回答「形状是否可迁移」—— 项目已有证据说明**尺度结构不可迁移**：陈表三档 ×k 86.1 / 59.5 相差悬殊）与 **`MAE/σ(y)`**。
⚠ 另测一条：把误差分解为「固定底 + 比例项」（`MAE ≈ a + b·y`）**对分层方式不稳健**（十分位给 12.4ms + 5.1%·y，按 6 角色给 −2.8ms + 22.2%·y 二者不一致）⇒ 该分解只能作「看形状」的辅助诊断，**不可当可移植定律**。

### 5.2 主精度（三档统一报表）

**偏差 (bias) 的定义（2026-10-08 起全项目唯一约定，三档共用）**：

> **偏差 = 预测 − 实测**（ms）。负 = 模型低估（预测比实测快），正 = 模型高估。
> 另有**段位偏差** = 该段角色上（预测段时长 − 实测段时长）的均值，以及**段级偏差**（全部段样本）。
> 段时 = 按键间 delta ⇒ **总级偏差 = 同一 trial 内段级偏差之和**（三段之和对 4 键即 T₄）。
> SE 一律取该层误差的 SD/√n（ddof=1），z = 偏差/SE。

**cost 定案的约束项是判据③而非②**（2026-09-22 实测，`实验/实验-错误修正成本定案测算.py`）：② 只看近 10 坐姿窗口内的斜率，而新数据一进窗就把早期高值坐姿（776/851/909）挤出，窗口自动变平——按现近 5 坐姿水平（710ms）续采 **+70 episode** 即达标；③ 比的是近端水平与**全体**均值，全体均值被练习期高值坐姿（903/892/909）抬高，只能靠新数据稀释下来，故 **+278 episode** 才是真正的门槛。注意 ③ 的语义是**平台检验**：若近端仍按 −17.7ms/坐姿 下行，全体均值同步下移，「近 5 vs 全体 <40ms」不会因样本量增加而达标——续采要看到的是坐姿均值**走平**（近 5 已连续停在 708/739/711/715/676 ≈710）。（③ 的达标量按新数据 ~710ms 外推；三判据现值：① 簇SE 29ms ✓ ② t=−2.52 ✗ ③ 差 −72ms ✗）

**混采产出（现行比例 3 键 50% / 4 键 30% / 2 键 20%）**：每 1000 trial 产出错误事件 31.5 个，其中 4 键 18.4 · 3 键 12.3 · 2 键 0.8 —— **每 trial 错误精度效率 4 键是 3 键的 2.5×、2 键的 15.0×**，这是"要错误精度就多采 4 键"的量化依据。

**结论与推荐比例**：**T₃ 族（表中前三行 + c2 格）是唯一便宜的一组，由 T₃ 偏差判定约束（+1085 三键 trial）**——采满这 1085 个三键 trial 同时满足 T₃ ±2ms（c2 格已达标），即 **+2171 trial（3 键 50% 份额）** 结清整组。⚠ **2 键份额的评估变了**：本刷 2 键稳定池缩到 905 trial（边界首次离开块 0），T₂ 留出只剩 181、SE 从 0.94 涨到 1.47ms——但 T₂ 判定门槛本身不值得为它加采（§5.7 表中该行 +211 二键 trial 只为把一个不显著的偏差判成显著），**结论是维持 2 键 20%（够维持角点片与 T₂ 监控），并把「2 键边界是否回摆」列为下刷观察项**。β 的约束**不是 c0 角点格**（去 γ 后此条作废，见 §4.6）：现约束项是 **c4 长尾格**（去掉它 β 的 SE ×1.34），由 4 键 30% 份额承担。

### 5.8 pa/pb 几何特征落地（φ19 → φ36，2026-10-07 用户决策）

**改了什么**：段特征从 φ19 扩到 **φ36** —— 追加 **pa 与 pb 两个键对的几何**，即 `[存在(prev), φ8(prev,a), φ8(prev,b)]` 共 17 维，prev=∅ 时整块为 0。**存在位只用一个**：pa 与 pb 的存在性同为「prev 是否为空」，两列在全部 18394 段上逐元素相同（用户指出后实测确认）——重复列对神经分支严格共线、对 XGB 只是列抽样扰动，故合并（这一步 18→17 维，见下方落地后的清理）。**这填补的是一个真实的表示盲区**：此前 pa/pb 只有嵌入双线性 W₁/W₃、没有几何，而 φ8 几何只覆盖了 ab 一对；对 4 键码 (w,x,y,z) 而言，`φ8(w,y)`、`φ8(x,z)`、`φ8(w,z)` 这三个非相邻对在"三段之和"里没有任何一段能算出来。**不改**：pn 不加、an/bn 维持 φsuc 里的部分几何、ab 的 φ8 不动、其余结构/口径/超参全部不变（神经分量参数 102,545 → 113,425）。

**为什么这么选（消融证据，`实验/实验-四对几何特征消融.py` 17 臂 + `实验/实验-六对特征两批复核.py`）**：

| 对 | 整对去掉的代价（相对四对全 8） | 结论 |
|---|---|---|
| **bn** | T₄ **+1.13** / T₃ +1.08 / 验证段 +0.44 | 最承重 |
| **pa** | T₄ **+0.61** / T₃ +0.88 / 验证段 +0.39 | 承重 |
| pb | T₄ −0.06 / T₃ **+1.67** / 验证段 +0.30 | T₄ 中性、T₃ 承重 |
| an | T₄ −0.10 / T₃ −0.09（**去掉还略好**） | 中性 → 不必扩，维持现状 |
| pn | —（另测：T₄ +0.01 / T₃ +1.26） | **纯负担，不加** |

- **pa/pb 的 8 个几何特征逐一 LOO**：去掉任一个，**验证段 MAE 8/8 全部变差**（+0.05~+0.14），但主指标 T₄ 上全落在 ±0.28 噪声内 ⇒ 特征间冗余、**但无一可删**，故取全 8（与 09-01 对 ab 做的 φ8 LOO 结论同型）。
- **an/bn 不需要扩到全 8**：用现状子集替换全 8，an T₄ −0.19（更好）、bn T₄ +0.02（打平）。现状子集内 6 维逐维 LOO 也全为正（+0.06~+0.29，bn 里最承重的是 Fitts）⇒ 一维都删不掉，**维持现状**。

**效果（受控口径：同一 B4b 掩码、同一测试集、同一固定 5 种子）**：

| 指标 | φ19（前） | 加几何（后） | Δ |
|---|---|---|---|
| T₄ 总 MAE | 36.18 | **35.35** | **−0.83** |
| T₃ 总 MAE | 29.78 | **26.37** | **−3.40** |
| 验证段 MAE | 21.96 | **21.40** | −0.56 |

（上表是**受控口径**：同一 B4b 掩码、同一测试集、同一固定 5 种子，衡量的是几何本身的贡献。存在位用 1 个还是 2 个对结果是噪声级差异，故沿用该臂。）

**两独立种子批复核**（项目对 ~1ms 级效应的门槛，记忆 09-01）：批 A（种子 0-4）T₄ −0.83 / T₃ −3.40，批 B（种子 5-9）T₄ −0.40 / T₃ −3.47 —— **同号**。T₃ 的收益（约 11%）远大于 T₄（约 2%），机制上说得通：3 键的 s2 拿到 `φ8(x,z)`（它的唯一盲区对），而 3 键角色数据稀疏（~700 训练段），**显式几何先验在稀疏处的边际价值最大** —— 与 §4.4「φ 的价值在稀疏三元组外推」一致。

**同时被证伪的两条路**（记录备查，避免重走）：① 把同样的盲区 φ8 并进**特征通道**无效（B1 +0.01 / B2 −0.14 且伤 T₃）；② 在训练损失里加**总时项**（`段MSE + λ·总时MSE`）单调变差（λ=0.3/1/3 → T₄ +0.10/+0.49/+0.95）；③ 事后在总时上挂 φ8 线性修正项**确实有 −0.83~−1.08ms 且两批同号**，但无法结构化落地（①②都失败）——**本次真正落地的收益来自特征扩展这条第三条路**。

**落地自检**（改动管线核心张量构造后的强制步骤，记忆 09-21 教训）：新增 `KJ_GEO=0` 开关退化旧配置 φ19 —— 逐位复现旧快照（训练池 B4b 17895/18394 段、测试集完整 trial 1115、段 23.8 / 总 36.2 / R²+0.672、角点 14.1/+0.3（旧符号）、T₃ 29.8/−7.4、陈表 ×k=1.012/排名 0.8044）⇒ **改动在关闭时不改变任何行为**；φ37→φ36 这一步之后**重跑该自检仍逐位通过**。

**落地后的清理（φ37 → φ36，同日晚）**：初版给 pa、pb 各配了一个存在位，但两者同为「prev 是否为空」、恒等（18394 段全等），属重复列。合并为一个后 φ 宽度 36、神经参数 113,425。**影响是信息中性的**：神经分支重复列严格共线（两权重之和 ≡ 一个权重），XGB 分支只是 `colsample_bytree` 的列抽样分布变了。实测主口径 T₄ 34.4→**34.5**、R² +0.703→+0.699、T₃ 25.5→26.8 —— **全在噪声带内**（B4b 掩码与测试子集又移动了一次：训练池 17910→17879 段、测试完整 trial 1121→**1112**），这反过来印证了那一列确实是冗余的。

**产物口径**：npz 结构**不变**（按键时间表 version 3 的 6 角色片、段当量表 version 5），只有数值变；`总当量-2-4键.txt` 格式与码序不变 ⇒ **下游 calc-schema / chai-windows 无需改代码**。当前（10-08 晚快照）主口径：T₄ **34.0** / R²+0.726 / 段 21.8（B4b 完整 1174）、T₃ 24.3 / −2.53、T₂ 14.8 / +0.32、陈表 4 码 ×k=1.002 / 排名 0.824；组装自检 T₂=56.2 / T₃=172.3 / T₄=358.2。

## 6. 讨论

### 6.1 局限性

- **串行假设**：段模型假设相邻击键串行。Dhakal et al. (2018) 显示熟练打字员 40-70% 的按键存在 rollover（重叠 30-100ms）——逐段求和可能系统性高估极快打字状态。实测（key-up 字段，释时全>0 无偏口径 10814 行，10-08 晚重算）：重叠比例首段 68.5%、中段 19.9%、尾段 48.3%，幅值中位 28-45ms，与文献区间一致——重叠集中在首段（静止启动加速期）与尾段（提前规划收尾），中段低重叠支持"段模型对中段串行假设最可靠"
- **字母身份残余效应**：刺激以字母呈现，拼音二元组熟悉度对键对耗时存在超出几何/手指特征的小效应（早期全量口径实测）——偏相关 −0.08（控制 φ8 与两键基线后），高熟悉键对比零熟悉约快 7-9ms，与表条目噪声同量级、远小于当量主效应。曾考虑改用键位图显示消除字母层，评估为弊大于利（打字技能按字母组织，位置刺激退化为找键认知任务）——维持字母显示
- **时间漂移（练习效应）**：采集期速度单调提升（早期 session 中段中位 208→157ms，-24.5%），且**按键对类型不均**（同指 -60ms > 同手 -42 ≈ 跨手 -39 > 同键 -13ms）——混期当量表对当前状态的难键对成本系统性高估。处理：**稳定期口径已落地**（§5.1 边界方法自动确定稳定期，训练/测试/部署均只用稳定期数据）
- **误差重尾**：飞行时间近似 log-logistic（重尾），沉思停顿可达数秒；B4b MAD 剔除处理了异常，但纯 MAE 对重尾敏感（可考虑分位数目标）
- **单用户**：模型为个人指法特征（含小指弱势等个体差异），人群外推需 136M Keystrokes 类数据验证

### 6.2 未来工作

（精度类扩容已证无收益，§5.2；下列均为非精度目标或远期条件性条目）

- **外推口径评估**：按三元组留出评估按键时间表外推误差——当前全局 MAE 掩盖了"2/3 条目零样本"的风险分布
- **人群先验**：136M Keystrokes 数据集（168k 人，公开免费）可作稀疏键对的先验/外部验证
- **rollover 显式建模**：key-up 字段已有——串行求和在高重叠段系统性高估，可按重叠类型修正整串口径
- **三元组交互**：Carpalx 的 k1:k2:k3 = 60:30:10 结构提示跨键对涌现惩罚，但三元组覆盖不足下三阶参数只会过拟合——数据量达标后再议
- **错误率数据积累**：~5-10 万 trial 后可升级 26 类指对嵌入/目标指难度特征（当前类别自由参数全部过拟合）

## 7. 结论与应用

本项目将击键时间成本建模从"2 键当量逐对累加"推进为"个人数据驱动的对称条件段模型"：段 S(段角色,p,a,b,n) 统一覆盖 2/3/4 键当量（同源同尺度，2026-09-21 起含段位/码长角色），错误成本按段类内含于"当量"定义。固定 trial 测试集上 4 键总时间 MAE 34.0ms、R² +0.726、排名精度 0.824，总级偏差 −0.32±1.31ms（**首次不显著**）；3 键留出指标 T₃ 24.3ms（偏差 −2.53±2.14ms，n=305）——绝对标定近完美（×k₄=1.002），且在 4 码/3 码/2 码三档上分别领先群体两键当量表 38%/46%/51%（**2026-10-07 pa/pb 几何落地，φ19→φ36，受控口径 T₄ −0.83 / T₃ −3.40，见 §5.8**）（§5.3，含特征层面的差异分解见 §5.3.1：陈表难度由"同手/跨手"主导，本项目由"同指"主导，两表在同指类键对上不可互替）。模型已贴实测噪声量级（§5.2），当前精度的剩余空间属组内生理噪声；后续条件性增益路径只剩两条：3 键偏差带宽（§5.7 给了数据量）、错误率模型的后键身份细化（中段上下文 P 随 n 摆动，错误事件 ~1200 时复验，§5.5）。错误率模型的交互项已按监控结论删除（§4.6），结构收敛为纯加法；同日**同指块重参数化为 {同指, 同键}**、**删掉自动选型把特征集固定**（2026-10-07 用户决策），再按消融与两独立批复核结果**把 小指-食指 加进部署（8→9 特征）**——该特征是"同手同指对越耦合越易错"这条线上的保护侧一端（1.79% vs 同手 2.46%），**晚刷符号复核 −0.32 同号 ✓**。**采集现状**：09-18 曾定档停采（52 session / 14017 行），当日因 3 键错误率隐患重启补采；09-21 段位特征落地后按数据充分性实测把混采比例重定为 **3 键 50% / 4 键 30% / 2 键 20%**（§5.7），**目标是把 T₃ 族这一项固定欠账（10-08 晚口径：T₃ 偏差判定 +1085 三键 trial，按现行份额折 +2171 trial）结清后回到「定档停采」**。另有两项监控/开项：**T₄ 总偏差本刷转正到 −0.32±1.31ms（z=−0.24 不显著，§5.7）**；**cost 定案**（§4.6/§5.7）——受判据③约束只差 +278 episode，而 `采集-错误修正时间.py` 自 2026-09-13 停更。本文数字与全部产物为 **10-08 晚快照**（70 session / 18679 行；φ36 已落地，**B4b 剔除口径 = 整 trial** + XGB 独热 122）。局限性（串行假设、字母身份残余效应、单用户）见 §6.1。

应用方式（应用域 = 4 码内词内评估，§4.8）：

- **编码方案评估**：将方案的常用编码代入总当量-2-4键.txt（错误成本已内含），计算平均击键总时间
- **键位优化**：调整个别键位映射后重新计算总当量，评估优化效果
- **键盘布局设计**：评估新布局的运动学效率（注意模型为 QWERTY 30 键采样训练，非 QWERTY 布局需重新采样）

                                         #    （输入法中文态可直接采; 排障 --no-ime 关闭禁用 IME）
python 分析-按键时间.py --full          # 2. 稳定期测试集评估 (T₄/T₃/T₂ 三留出指标) + 部署模型训练 → 产物/按键时间表 npz (6 角色片) + 模型双文件
                                         #    （自动输出陈一凡表对比 §5.3——数据 数据/陈一凡当量表.txt）
python 分析-错误率.py                   # 3. 错误率模型（全量数据, 段类 5 类）→ 产物/键对错误率表.txt
python 采集-错误修正时间.py             # 4a. 错误修正时间采集（连续长随机串 GUI；同样无视输入法，排障 --no-ime）→ 数据/错误修正时间-错误键.tsv
python 分析-错误修正时间.py             # 4b. 错误修正时间聚合 → 产物/错误修正时间-实测值.txt（含定案判据报告）
python 组装当量表.py                    # 5. 产物/段当量表.npz（6 角色片 = 按键时间+实测cost×P_err）+ 产物/总当量-2-4键.txt（段当量求和）
python sync_github.py                   # 6. 同步代码+数据到 GitHub（--dry-run 预览；**产物不入 git**，见「产物分发」）

### 产物分发（2026-09-22 定：产物不由 git 管理）

产物七件 (~20MB) 每次数据刷新整体换新、历史产物无参考价值，且本机网络对 GitHub 附件/HTTPS 不可靠
（见下）——故**产物彻底不入 git、不发布**：**只在本机 OneDrive `串击击键当量/产物/` 保留最新一份**，
下游（calc-schema 等）直接读该目录。主仓库只放代码 + 采集数据 + 本文档（克隆 ~4.7MB / `.git` ~3.4MB）。

演进记录（供查证）：09-06 产物首次入库 → 09-18 曾决策「最终快照随仓库分发」→ **09-21 用
`git filter-branch --index-filter 'git rm -r --cached --ignore-unmatch 产物'` 自全部 40 个提交剔除
并 force-push**（`.git` 25MB→2.6MB，`.gitignore` 加 `产物/` 规则作安全网）→ 同日试过 GitHub Release
附件与独立产物仓库两条通道 → **09-22 用户决策「产物不需要用 git 管理，本机保留最新产物就行」，
两条通道全部废弃**（`sync_github.py` 只同步代码 + 数据）。

**本机网络实测（2026-09-21，跨项目通用）**：① `release-assets.githubusercontent.com` 不可靠 ——
上传端 gh 对非 ASCII 附件名会退化成 `default.npz`，下载端 2 次测试 1 次 TLS handshake 超时、
1 次**静默截断**（只下到 3.6MB / 应有 12.4MB）；② HTTPS 访问 github.com 被 reset
（`Recv failure: Connection was reset`）→ **一律用 SSH 远端**；③ git(SSH) 推 12-20MB 稳定。

**注意**：主仓库 history 已于 09-21 重写，其它机器上的旧克隆需重新 clone（不能 pull）。

### 同步纪律与不可用通道（2026-09-22 定；分发策略与网络实测见上节）

- **主仓库 `conditional-keystroke-timing`**：只放**代码 + 采集数据 + README**（13 文件 / 45 提交 / `.git` ~3.4MB）。同步脚本 `sync_github.py` **单通道**（清单 `SYNC_FILES`），同步副本 `D:/conditional-keystroke-timing`，远端用 **SSH**（本机 HTTPS 会被 reset）。
- **产物不入 git、不发布**：只在本机 `产物/`（OneDrive 规范源）保留**最新一份**，下游 calc-schema / chai 直接读该目录。仓库 `.gitignore` 保留 `产物/` 规则作安全网。
- 规则：改完方案/脚本先跑 `python sync_github.py`（+ `--dry-run` 预览）；**同步后必须 `git ls-files` 核验实际入库**（.gitignore 曾静默吞文件）。
- 不可用通道（2026-09-21 实测，勿重试）：GitHub Release 附件（gh 会把非 ASCII 附件名改成 `default.npz`；下载 `release-assets.githubusercontent.com` 1/2 次 TLS 超时、1 次静默截断）· 独立产物仓库（09-22 废弃）。
